## 改善課題

### 0. カテゴリと主要材料

「手元にある材料から今日作るものを決める」が中心ユースケースなので、カテゴリと主要材料はMVPに含める。単なる自由タグではなく、検索順位に使う構造化データとする。

- `categories`：主菜、副菜、主食、丼・ごはん、麺など
- `main_ingredients`：豚肉、鶏肉、魚、卵、豆腐、なすなど

「豚肉」で検索した場合、豚バラ・豚こま・豚ひき肉を主要材料とする料理を上位にする。調味料や少量の具材は主要材料にしない。

### 1. タイトルの正規化

現在は次のようなキャッチコピーがタイトルに残っている。

```text
じゅわっとジューシー♪ ガーリックトースト
コスパ最強文句なし！ピリ辛よだれ厚揚げ
『なすの肉巻き』男子の胃袋掴みます
```

レシピ集内では、次のような短いタイトルにする方が検索・表示に向いている。

```text
ガーリックトースト
ピリ辛よだれ厚揚げ
なすの肉巻き 甘辛すき焼き風
```

プロンプトを更新済み。次回変換で確認する。

### 2. メモの情報量

栄養成分や費用情報まで `notes` に入っている。料理中の用途ではノイズになるため、次回から料理のコツ・注意・ユーザー独自メモを優先する。

### 3. 分量の表示形式

内部値は現在のように `amount` と `unit` を分けてよい。ただし、表示時には次のように自然な日本語へ整える必要がある。

```text
amount: "2", unit: "大さじ" → 大さじ2
amount: "1/2", unit: "小さじ" → 小さじ1/2
```

これはLLMの問題ではなく、ビューア側の表示ロジックで解決する。

### 4. 人数不明レシピ

暗殺者のパスタと麻婆茄子は、入力に元人数がないため人数換算できない。これは変換失敗ではない。ビューアでは「人数換算なし・原文量で表示」とする扱いを検討する。

現時点では3件だけが新スキーマで、残り7件は旧スキーマのままである。プロンプトとスキーマをこの形で確定し、次に10件全体を再変換する。

## 10件全体の再変換結果

10件を新しいスキーマで再変換した。エラーはなく、全件にカテゴリと主要材料が付与された。

### カテゴリ

- 主菜：なすの肉巻き、トマトと卵の炒め物、豚ニラ玉、麻婆茄子

「主菜かつ別の用途」「パン・軽食かつおつまみ」のように複数カテゴリを持てるため、現時点の分類として自然である。

### 主要材料

「豚肉」「なす」「トマト」「卵」「パスタ」など、手元の材料から探すための一般分類が付与された。具体的な材料名は aliases に入り、豚バラ・豚こま・豚ひき肉を「豚肉」で検索できる構造になっている。

### 要確認として妥当なもの

- 暗殺者のパスタ：元人数がない
- 麻婆茄子：元人数がなく、入力テキストにも動画内の詳細手順がない

いずれも入力情報の不足であり、モデルが勝手に補完せず `review_flags` に出している。Phase 0の期待する挙動である。
