# URL入力検証レビュー

## 実施内容

`tools/url_phase1.py` で、通常のレシピサイト5件とYouTube 2件を、URLだけからJSON化した。OpenAI Responses APIのWeb検索ツールを使用し、同じ7件を2回実行して再現性も確認した。

出力は `phase1-url-output/recipes/` に保存している。このディレクトリは `.gitignore` 対象である。

## 結果

通常サイトは、5件ともJSON化に成功した。

| 種類 | 結果 |
| --- | --- |
| macaroni ガーリックトースト | タイトル・2人分・15分・材料6件・手順8件。実用水準 |
| DELISH スタミナ豚ニラ玉 | タイトル・2人分・10分・材料13件。実用水準 |
| DELISH 無限ナス | タイトル・2人分・10分・材料8件・手順8件。実用水準 |
| Nadia ツナチーズ焼きトマト | 2人分・15分・材料5件。手順の並べ方に要確認フラグ |
| Nadia なすの肉巻き | タイトル・2人分・15分・材料15件。実用水準 |

通常サイトは、PDF版と比較して料理中に使える水準だった。ただし、同じ内容でも次のような構造差は出た。

- `大さじ1杯` を `amount=大さじ1杯` とするか、`amount=1 / unit=大さじ` とするかの揺れ
- `塩、こしょう` を1項目にまとめるか、2項目に分けるかの揺れ
- 手順の分割数の揺れ

これは表示上は大きな問題ではないが、人数換算や編集画面では正規化ルールを追加したほうがよい。

## YouTube結果

### 暗殺者のパスタ

1回目は概要欄から材料11件と手順11件を取得できた。しかし、人数が記載されていないのに `servings=1` と推定されたため、プロンプトを修正した。

2回目は、材料・手順を取得できず、`review_flags` に要確認として残った。

同じURLで結果が変わったため、URLをLLMに直接渡す方式は、YouTubeでは再現性が不足する。

### 麻婆茄子

2回とも材料は取得できた。2回目は手順も15件取得できたが、動画内容に依存する油の分量について要確認フラグが付いた。

概要欄に材料があるYouTube動画は試す価値がある。ただし、手順の完全な取得は保証できない。

## 結論

- 通常のHTMLレシピサイト：URLをLLMに渡す方式でも検証上は実用水準
- YouTube概要欄：材料抽出は有望、手順は要確認前提
- YouTube動画本体：今回の方式だけでは不足
- 同一URLで結果が揺れたため、URL直渡しを本番の唯一の経路にはしない

## 次の方針

Phase 2では次の優先順位にする。

1. 通常サイトは本文を取得・保存してからLLMに渡す
2. YouTubeは概要欄を取得できた場合のみ候補生成する
3. 字幕取得は別の追加機能として検討する
4. URL直渡しのWeb検索は取得失敗時のフォールバックにする

また、変換後は必ず人間が確認して確定保存する。特に `servings` が不明な場合は推定せず `null` にする。
