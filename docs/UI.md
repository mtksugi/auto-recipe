# UI仕様

## 用語

利用者向け画面では、LLMやnormalizeなどの実装用語を使わない。

- 閲覧画面: 「レシピ一覧」
- 登録画面: 「レシピを追加」
- URL・ファイルの解析: 「レシピを取り込む」「レシピを読み取る」
- 確認済みデータの登録: 「この内容で保存」

登録は「取り込み元を選ぶ → 内容を読み取る → 確認・修正する → 保存する」の順に案内する。

## 画面間の移動

レシピ一覧とレシピ追加の両画面に相互リンクを置く。スマートフォンのレシピ詳細には「レシピ一覧へ」を置き、料理中でも一覧へ戻れるようにする。

## レシピ詳細のURL

選択中のレシピは `/?recipe={recipe-id}` で表現する。

- 一覧でレシピを選ぶとHistory APIで履歴を追加する。
- ブラウザの戻る・進む操作で選択状態を復元する。
- URLを直接開いた場合も対象レシピを表示する。
- 存在しないIDはパラメーターを除去し、安全に一覧を表示する。
- 絞り込みによって選択中レシピが対象外になった場合は選択を解除する。

## 取り込み

取り込み方法は「URLから」「ファイルから」のタブで明示的に選択する。非表示側の値は送信しない。対応ファイルはPDF、画像、テキストで、上限は15MBとする。

読み取り中は不定進捗のローディング表示を出し、入力、タブ、送信ボタンを無効にして二重送信を防ぐ。成功・失敗のどちらでも操作可能な状態へ戻し、失敗時は入力を保持する。

## 料理中の画面表示

レシピ詳細に「画面を消さない」切り替えを置く。利用者が有効にした場合のみScreen Wake Lock APIを要求する。

- 一覧へ戻ると解除する。
- ページが再表示されたとき、有効状態なら再取得を試みる。
- API非対応や端末による拒否があってもレシピ閲覧は継続する。
- 取得できない場合は端末設定を確認する案内を表示する。

## 操作性

料理中に使う主要操作は、スマートフォンで押しやすいタップ領域を確保する。人数変更、一覧へ戻る、画面消灯防止、画面間リンク、取り込みタブと送信ボタンを対象とする。

## 今後の管理機能

保存済みレシピの編集と削除は別の改善として扱う。削除は確認操作を伴う完全削除とし、利用者向けのゴミ箱や復元機能は設けない。
